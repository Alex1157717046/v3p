## 一、结论摘要

原方案 **80% 可用**，但有 **3 处必须先修正**，其中 1 处会直接删掉整个实验：

| # | 原方案 | 核实结果 | 影响 |
|---|---|---|---|
| ★1 | 功率级 = 分立 NMOS + **EG2133** | 实为 **FD6287T**（+1 片 FD6287） | E0.1/E1.7 的器件型号、参数全要改 |
| ★★2 | 「V3P 死区由 MCU 决定 → **死区扫描实验可做**」 | ❌ **不成立**。板上 `HIN_i` 与 `LIN#_i` 短接，每相只有 1 根 MCU PWM → 死区完全由 FD6287T 内部固定（100/200/300 ns） | **E1.6 从"扫描"改为"测量+补偿"** |
| ★3 | 「ESP32 的死区设置直接生效」 | ❌ 官方 DengFOC 用 **LEDC**（无死区功能），且本板也没法插死区 | 同上 |

其余结论（inline 电流采样、±3.3 A 量程、2208 电机参数、低载波比人造场景、观测器用编码器做真值…）
**全部成立**，且方案里"用降 fsw 造低载波比"这个技巧依然是整份材料里最有价值的一招。

## 四、★ 核心更正：死区到底能不能调？（E1.6 的生死问题）

### 4.1 证据链

**证据 1（决定性）**：把 `V3P驱动板最新版原理图.pdf` 中 FD6287T 输入端放大到 1200 dpi 后可见，
六个输入引脚 `HIN1 HIN2 HIN3 LIN1# LIN2# LIN3#` 所连的网络标签是：

```
M0_IN1  M0_IN2  M0_IN3  M0_IN1  M0_IN2  M0_IN3
```

**同一组网络各出现两次** —— 在 EDA 里这就等于把它们短接。即：

```
        ┌──────────────────────┐
M0_IN1 ─┤ HIN1        FD6287T  ├─ HO1 → M0_GH1 → 上管栅极
M0_IN1 ─┤ LIN1#                ├─ LO1 → M0_GL1 → 下管栅极
        └──────────────────────┘
```

**证据 2**：V3P 板的 ESP32 插座（H2/H3）只引出 `M0_IN1/2/3`、`M1_IN1/2/3` 共 6 根 PWM 信号，
**没有任何一路 LIN# 的独立信号**。物理上就没有第二根线可用。

**证据 3**：FD6287T 原厂手册 §10「死区功能」原文：

> "如果逻辑输入设置的外部死区时间**大于**芯片内部设置的死区时间，则以逻辑输入设置的外部死区时间为芯片输出死区时间；
> 如果逻辑输入设置的外部死区时间**小于**芯片内部设置的死区时间，则芯片输出的死区时间为芯片内部设置的死区时间。"

即 `最终死区 = max(MCU设定, 芯片内置200ns)`，**叠加关系是取大值，不是相加**。

### 4.2 结论

| 问题 | 答案 |
|---|---|
| 死区能由 MCU 设置吗？ | **不能**。每相只有 1 根 PWM，HIN/LIN# 短接，驱动 IC 自己产生互补与死区。 |
| 死区实际是多少？ | **FD6287T 内置：100 / 200 / 300 ns（min/typ/max）**，且有硬件互锁（防直通）。 |
| 能用软件插入死区吗？ | **不能**。duty=1 时下管必开、duty=0 时上管必开，造不出"上下管同时关断"的窗口。 |
| "死区扫描实验"能做吗？ | **不能**（除非改板：割断 LIN# 与 HIN 的连线，飞线到空闲 GPIO 由 MCU 单独驱动）。 |
| 还能做什么？ | ✅ **① 死区测量**（示波器量 GH/GL，见 E1.7②）；✅ **② 死区电压补偿**（E1.6 重写版）。 |

### 4.3 顺带更正另外两条

- 原方案引用"EG2133 内建死区约 100 ns"→ 实际芯片是 **FD6287T，typ 200 ns**。
  （旁证：**EG2133 与 FD6287T 是 20 脚逐脚兼容的**，这也是为什么很多分析文把两者混为一谈。）
- 原方案说"TIM1 互补输出 + BDTR 死区寄存器与 EG2133 的 6 路输入严丝合缝"→
  在这块**转接板**上同样只有 3 路 PWM 引到驱动板，所以 STM32 侧也**用不到** BDTR 死区。
  这个"优势"在本硬件上不成立（但作为知识仍然值得学）。

### 4.4 死区在 2208 电机上本来就不明显

`ΔV = (Td/Ts)·Vdc = (200 ns × 20 kHz) × 12 V = 0.048 V`，
畸变电流 `ΔV/Rs = 0.048/10 = 4.8 mA`（占额定 2 A 的 0.24%）。

**所以原方案"要用低阻航模电机才能把死区现象放大"这一条是对的**，
换 `Rs≈0.1 Ω` 的电机后同样的 0.048 V 会变成 480 mA —— 现象才明显。

## 六、★ STM32 转接板：已逆向出完整引脚映射，并发现 2 个硬伤

完整逐针对照表见 **`docs/STM32转接板引脚映射对照表.md`**（含 40 针逐一取证、复现脚本与 600/1200 dpi 证据图）。

### 6.1 最终映射（V3P 功能 → STM32F103C8T6）

| V3P 信号 | STM32 引脚 | 外设资源 |
|---|---|---|
| M0_IN1 / M0_IN2 / M0_IN3 | **PA0 / PA1 / PA2** | TIM2_CH1/2/3 ✅ 同一定时器 |
| M1_IN1 / M1_IN2 / M1_IN3 | **PA3 / PA6 / PA7** | TIM2_CH4 + TIM3_CH1 + TIM3_CH2 ❌ **跨两个定时器** |
| M0_OUT1_CS / M0_OUT2_CS | PB0 / PB1 | ADC12_IN8 / IN9，可注入 ✅ |
| M1_OUT1_CS / M1_OUT2_CS | PA4 / PA5 | ADC12_IN4 / IN5，可注入 ✅ |
| SCL_0 / SDA_0（M0 编码器） | PB10 / PB11 | I2C2 ✅ |
| SCL_1 / SDA_1（M1 编码器） | PB6 / PB7 | I2C1 ✅ |
| TXD / RXD | PA9 / PA10 | USART1 ✅ |
| MOTOR_EN | 本意 PA8 | ⚠ 见 6.2 |

### 6.2 两个硬伤（会直接让实验失败）

**硬伤 1：M1 的三路 PWM 跨了 TIM2 和 TIM3。**
`PA3 = TIM2_CH4`，而 `PA6/PA7 = TIM3_CH1/CH2`。
→ 无法用"一个定时器 + 3 个 CCR"生成三相同步 PWM，两路的载波相位与 ADC 触发时刻会错位。

*补救*：① 改板（把 PA3 与 PB0 互换，M1 就全落在 TIM3，且电流采样仍全在 ADC 引脚上）；
② 软件补救：TIM2 作主机 TRGO 触发 TIM3 从机，PSC/ARR 对齐后同时启动（需实测验证相位）。

**硬伤 2：`MOTOR_EN` 在网表上根本没连到 `PA8`。**
转接板 E2.12 上写的是 `MOTOR_EN` + 全局标签 `PA8`，而 STM32 侧 S2.5 的网名写的是 **`A8`**（少了一个 P）。
本图完全靠"网名文字相同"连接，所以这两个网络是**互相独立的单点网络**。
→ 按现图，栅极驱动的使能信号是悬空的，**驱动板可能根本不工作**。

*补救*：把 `A8` 改成 `PA8`（或反之）；**动手之前先用万用表量 S2.5 ↔ E2.12 是否真的不通**。

### 6.3 对原方案附录 G 的更正

| 原方案说法 | 核实结果 |
|---|---|
| "STM32 的 TIM1 互补输出 + BDTR 死区寄存器与这块板严丝合缝" | ❌ 不成立。TIM1 的引脚在本设计里给了 MOTOR_EN / TXD / RXD / 空网络，**完全没用上 TIM1**；而且本板只需要 3 路非互补 PWM（§四），互补输出本身就是多余的 |
| "STM32 外设更专业（注入 ADC、互补 PWM、BKIN）" | 部分成立：**注入 ADC 真能用**（4 路都可注入、可 ADC1/ADC2 同步采 2 路）；互补 PWM/BKIN 在这块板子上用不到 |
| "STM32 路线唯一必须先搞清的是引脚映射" | ✅ 说对了，而且现在**已经搞清了** —— 代价是发现上面两个硬伤 |

### 6.4 STM32 路线能不能用？结论

- **M0 单电机**：✅ 完全可用（TIM2 三通道 + ADC 注入）。
- **M1 单电机**：⚠ 需要软件同步 TIM2/TIM3，或改板。
- **双电机同时 FOC**：⚠ 更难（两路电流采样无法同时注入，最多 2 路同步）。
- **母线电压检测**：❌ 转接板没把 `POWER_ADC` 引出来（E1.9 打 X），要用得自己飞线。
- **推荐的阶段 4~5 MCU**：**先用 ESP32 把观测器/辨识做完**（浮点方便、外设够用），
  STM32 留给阶段 7 的定点化对比 —— 这也正好符合原方案"先 ESP32 后 STM32"的主张。
